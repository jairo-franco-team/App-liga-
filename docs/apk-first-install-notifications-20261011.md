# APK first installation and notification preferences

First installation opens the four requested references in order: privacy introduction (05), cookie/data consent (04), actual Liga clubs (03), and notification activation (02). This is a real dialog with controls, not screenshot wallpaper. The new module only starts on Android's first installation; upgrades, completed/skipped flows, and an existing authenticated profile stay on their current app screen.

Files: `src/apk-first-install-20261011.js`, its scoped CSS, state module, and 51-club catalog. Root index hooks are the stylesheet and module script. `v25-following-reference.js` gained the missing official POZOS FC V35 entry so its own migration cannot discard the chosen club. Clubs shared between categories retain the existing multiple following IDs. All logos come from packaged actual season assets.

The original ZIP supplied four abstract/empty assets: phone frame 28,296 bytes, notification background 58,316 bytes, privacy background 11,794 bytes, and teams background 4,630 bytes (103,036 total). These contain no foreign team names or logos; the notification cards are generic Liga explanatory content, never invented live results. Their paths are `public/reference-ui/onboarding-*.webp`.

Root causes: the “Preferencias actuales” card navigated to its already-current hash, so no navigation event opened the settings. V46 and profile-smart requested browser Notification inside Android; V840 intercepted the device button without updating its status copy. Android versions below 33 returned permission true unconditionally, even if the app/channel was disabled. Legacy account and app preference stores could disagree, so an enabled account switch could remain disabled for delivery.

The module handles the actual card click, scrolls/focuses the current settings, reconciles account/store/runtime notification preferences, and shares one Android permission API with V840 and profile-smart. Permission checks never request access. Refusal and blocked settings remain visible after returning from Android Settings. Read-only checks coalesce; equal status text does not write DOM, equal permission state does not render the feed, and the observer ignores its own text/feed changes. Returning to a notification/settings route rechecks actual permission.

The existing LigaNotifications Android bridge now exposes read-only status, app/channel checks, installation detection, persistent completion, and the Android notification settings screen. Native completion lives in SharedPreferences; WebView completion/pending step/selection also persist locally. Preference updates preserve the profile, favorites and existing following IDs. Optional consent only controls local personalization and does not enable analytics or new external sharing.

Validation: fail-first Node tests cover first-install/upgrade/completion eligibility, order/resume, consent, actual club IDs, user preservation, refusal/errors, current-settings click, native profile handler without browser Notification, status restoration and DOM write/request/render bounds. Native contract tests check exposed Java methods and actual app/channel guards; these are source-contract checks, not Android execution. `tests/onboarding-mobile-v1460.mjs` targets the real compiled app at 360×800 and 412×915, captures all four steps, picks POZOS, verifies consent/refusal/completion/relaunch/upgrade/existing-account behavior, and blocks all external traffic. Only the OS plugin boundary is simulated. It is intended for root's CI browser, not a local browser.

No Android SDK/javac or handset is available in the task environment. Android compilation and a real phone permission/delivery test remain necessary. Local Android permission does not establish remote delivery with the APK closed. The repository's optional FCM receiver/configuration has auto-initialization disabled and no opt-in token registration bridge in this module; remote registration still requires the existing authenticated service/configuration. Web Push remains the existing V1082 service/panel and is neither replaced nor silently subscribed. SMS, WhatsApp, email and new providers are not used.
